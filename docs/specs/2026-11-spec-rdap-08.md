# Spec 8: RDAP for netblocks and registrants

## Goal

The netblocks registered to an input organisation are found in each regional registry that offers
organisation search, not just RIPE's, and the registrants of in-scope addresses are recorded as
structured data so related organisations surface as candidates. Nothing found this way enters
scope on its own.

## Behaviours

1. An `rdap` stage, available under `--passive`, contacts only IANA and the five regional
   registries. Lookups by address use the IANA bootstrap to choose the registry; organisation
   searches go to every registry that supports them, which the README lists. A lookup the registry
   refers to a server outside those six completes with no data and a `--verbose` warning naming
   the address.
2. For each `--org` input, netblocks and autonomous systems returned are recorded as candidates
   in `candidates.csv` with source `rdap`; the user passes one as `--cidr` or `--asn` to bring it
   into scope. A result is kept only when its registrant name contains every word of the `--org`
   name, ignoring legal suffixes (the same rule as the existing org pivot), up to 50 per registry;
   a truncated result produces a `--verbose` warning. A registry without search support completes
   with no results and a `--verbose` note.
3. For each recorded address that is port-eligible or inside an in-scope netblock, is not shared
   provider infrastructure and is not inside an input or ASN-expanded netblock, one lookup
   records the registered netblock, the registrant name and the registry. Addresses inside a
   registered netblock already looked up reuse that answer. `ips.csv` keeps the announcing
   network's `owner` and adds `registrant`, `registrant_netblock` and `registry` columns.
4. A registrant seen on three or more distinct registered netblocks, whose addresses recon does
   not classify as shared provider infrastructure, and whose name does not match an input `--org`
   by the rule in behaviour 2, appears in `candidates.csv` as a candidate of type `organisation`
   with the netblock count as its evidence. `candidates.csv` gains the `organisation` and `asn`
   types.
5. A 429 from any registry stops the stage for this run, as for other quota-limited sources; the
   remaining checks are retried next run.
6. Each lookup is made once per engagement and refreshed only by `--redo rdap`. The bootstrap
   file is fetched once per run.
