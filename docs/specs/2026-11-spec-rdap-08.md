# Spec 8: RDAP for netblocks and registrants

## Goal

The netblocks registered to an input organisation are found in each regional registry that offers
organisation search, not just RIPE's, and the registrants of in-scope addresses are recorded as
structured data so related organisations surface as candidates. Nothing found this way enters
scope on its own.

## Behaviours

1. An `rdap` stage, available under `--passive`, contacts only IANA and the five regional
   registries. Lookups by address use the IANA bootstrap to choose the registry; organisation
   searches go to every registry that supports them, which the README lists. A lookup the registry
   refers to a server outside those six completes with no data and a `--verbose` warning naming
   the address.
2. For each `--org` input, netblocks and autonomous systems returned are recorded as candidates
   in `candidates.csv` with source `rdap`; the user passes one as `--cidr` or `--asn` to bring it
   into scope. A result is kept only when its registrant name contains every word of the `--org`
   name, ignoring legal suffixes (the same rule as the existing org pivot), up to 50 per registry;
   a truncated result produces a `--verbose` warning. A registry without search support completes
   with no results and a `--verbose` note.
3. For each recorded address that is port-eligible or inside an in-scope netblock, is not shared
   provider infrastructure and is not inside an input or ASN-expanded netblock, one lookup
   records the registered netblock, the registrant name and the registry. Addresses inside a
   registered netblock already looked up reuse that answer. `ips.csv` keeps the announcing
   network's `owner` and adds `registrant`, `registrant_netblock` and `registry` columns.
4. A registrant seen on three or more distinct registered netblocks, whose addresses recon does
   not classify as shared provider infrastructure, and whose name does not match an input `--org`
   by the rule in behaviour 2, appears in `candidates.csv` as a candidate of type `organisation`
   with the netblock count as its evidence. `candidates.csv` gains the `organisation` and `asn`
   types.
5. A 429 from any registry stops the stage for this run, as for other quota-limited sources; the
   remaining checks are retried next run.
6. Each lookup is made once per engagement and refreshed only by `--redo rdap`. The bootstrap
   file is fetched once per run.

# Design

**Status:** ready to build (wave 2). **Depends on:** Spec 1 (`ErrQuota`, `Warnf`), Spec 15
(candidate model, `internal/orgname`); re-check the candidate types against `internal/candidates`
once Spec 15 has merged.

## Decisions

- **One stage, `rdap`**, in `internal/stages/rdap`, with sources `data.iana.org` and the five
  registry RDAP hosts. A request anywhere else is impossible (egress checks `Sources()`).
- **Bootstrap once per run**: the stage fetches `ipv4.json` and `ipv6.json` lazily through
  `sync.OnceValues` on its first check; a failure fails the checks of this run and they are
  retried on the next.
- **Referrals are followed by hand** (the third-party client never follows redirects): a
  `Location` on one of the six hosts is requested, up to three hops; any other host completes the
  check with nothing and a `run.Warnf` naming the address.
- **Address lookups.** `Checks` yields `ip|<addr>` for each recorded address that is port-eligible
  or in an in-scope netblock, not shared, and not inside an input or ASN-expanded netblock, unless
  a current `registration` record already covers it, and always yields `ip|<asked>` for each
  current `registration` (the address whose lookup produced it, kept in the record). Without the
  second rule `--redo rdap` would yield nothing, sweep every registration and fetch none again. A
  per-run cache in the stage answers later addresses of the same registered range without a
  request. The result is a `registration` record keyed by registry and handle: `start`, `end`,
  `registrant`, `registry`, `handle`, `asked`.
- **`ips.csv`** gains `registrant`, `registrant_netblock`, `registry`, filled by a range lookup
  over `registration` records; `owner` is unchanged.
- **Organisation search.** `Checks` yields `org|<org>|<registry>`. A registry without entity
  search completes with nothing and a note. Results are filtered by `orgname.Matches`, capped at
  50 per registry with a truncation warning. Netblocks are `netblock` observations (candidates by
  the existing scope rule, with `org` set); an RDAP range that is not CIDR-aligned is split into
  its CIDRs first, because a netblock key that is not a prefix is never shown; autonomous systems are a new kind `candidate_asn`
  (key `AS<n>`; `org`, `registrant`, `registry`), listed in `candidates.csv` as type `asn` while
  the ASN is not an input.
- **Organisation candidates are derived on read** in `internal/candidates`: a registrant on three
  or more distinct `registration` ranges, none of whose recorded addresses are shared, and not
  matching an `--org` input, is a candidate of type `organisation` whose evidence count is the
  range count and whose source is `rdap`. It is promoted with `--org`.
- **Evidence**: the stage implements `run.Evidencer`, returning (`rdap`, the organisation) for
  organisation checks, so a result is a registrant-family match of the input organisation.
- **A 429 is `ErrQuota`.**

## Tests

`internal/cli/rdap_test.go`, with fakes for IANA and the registries:

- An address is looked up at the registry the bootstrap names; a second address in the same range
  costs no request; excluded classes of address are not looked up.
- A referral inside the six is followed; one outside completes with a warning and no data.
- Organisation search: only word-rule matches are kept; 50 per registry with a warning; a registry
  without search completes with a note; netblocks and ASNs are candidates, never in scope.
- A registrant on three ranges becomes an `organisation` candidate; one matching `--org`, or on
  shared addresses, does not.
- A 429 stops the stage and the checks run next time; each lookup happens once and again only with
  `--redo rdap`; `--redo rdap` with two addresses in one range and no `--org` fetches the range again once; the
  bootstrap is fetched once per run; `--passive` runs the stage.
